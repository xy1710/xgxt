# 学管系统 E2E 实测报告（2026-10-21）

## 一句话结论

**「缴费 → 分班 → 接收建档」主链路跑通，新学号规则 `LZJ101001` 真实生成**；过程中抓到并修复了 **1 个 P0 级代码缺陷 + 4 处数据库缺列/缺表**（均为远程代码"只进建库 SQL、漏迁移"的系统性问题）。

## 三、抓到的问题（全部已修复）

### P0-1 财务核对不同步咨询侧 → 「缴费→分班」主链路断裂（代码缺陷，已修）

- **现象**：财务核对成功（pay_status=3），但咨询侧收款单永远停在"待财务确认"（status=1），分班前置校验（已到账）永远不满足 → **整个分班入档功能对所有用户不可用**
- **根因**：`finance/services/fee.service.ts` 的 `verifyFee` 只更新财务侧，没有任何回写咨询库的机制
- **修复**：verifyFee/rejectFee 增加跨库回写（两库同进程同实例，全限定名更新 `sms_consult.t_consult_fee_order`，按 finance_fee_id 反查）；`tsc --noEmit` EXIT=0，热重载后实测回写生效

### P0-2~P1-5 数据库缺列/缺表（5 处，远程代码"只进 sql/init、漏迁移"）

| # | 位置 | 缺什么 | 后果 |
|---|------|--------|------|
| 1 | sms_consult.t_consult_student | referrer_name / referrer_phone | 新增咨询学员直接 50002 |
| 2 | sms_consult.t_consult_fee_order | plan_id / stage_no / total_due_amount / item_detail | 咨询收费直接 50002 |
| 3 | sms_consult | t_consult_installment_plan / t_consult_installment_item 两张表不存在 | 分期付款功能不可用 |
| 4 | sms_consult.t_consult_student | arrear_amount | 欠费相关功能风险 |
| 5 | sms_finance.t_finance_fee | item_detail（**连 sql/init 都漏了**） | 咨询收费直接 50002 |

- **已修复**：所有缺列补齐、两张分期表按 sql/init 原样建出；补了团队缺失的迁移文件 `migrations/20261021_002_add_consult_referrer.js`
- **系统性根因**：**consult 库的迁移链是断的**——`sms_consult.knex_migrations` 只有 8 条（停在 10-02），而 migrations/ 目录有 33 个文件（到 10-19）；consult 历史迁移文件本身也没搬进仓库。**建议团队**：knexfile 增加 consult 专属 env + migrations-consult 目录，把 10-04 之后漏跑的迁移补录
