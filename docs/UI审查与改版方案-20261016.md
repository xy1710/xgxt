# 学管系统 UI 审查与改版方案

> 审查人：UI Designer（像素君）
> 日期：2026-10-16
> 范围：web-job 全站 56 页 / 7 模块（登录页、主框架、列表页、仪表盘、弹窗、表单）
> 方法：通读主导航配置、三套全局样式表与 12 个代表性页面的模板与样式实码，不凭印象

---

## 一、总体诊断

功能骨架是完整的——三层权限、合并学段、审批链都跑通了。但界面是**以后台模块为中心**长出来的，不是**以使用者的任务为中心**设计的。昨天已完成配色统一（良志红暖色体系），那只解决了「颜色」一层；结构性问题一层没动。

按严重度排序，有三类系统性问题：

| # | 问题 | 严重度 | 影响 |
|---|---|---|---|
| 1 | 导航按组织架构排，不按人的任务排 | ★★★★★ | 每天都要滚动找页面，新人找不到功能 |
| 2 | 三套设计系统并存（形制不统一） | ★★★★ | 每个模块长得像不同的产品 |
| 3 | 交互反馈大量欠账（空态/骨架/撤销/对比度） | ★★★★ | 界面「能用但费劲」，误操作不可逆 |

## 二、信息架构（最该动的一层）

### 2.1 侧栏是「56 页花名册」，不是导航

现状：7 个顶级分组平铺全部 56 页，其中「教学管理」一组就 16 项，占满整整一屏；用户找一个功能要滚动 + 肉眼扫描。

**建议**：侧栏只放两层——「我常用的 / 待办」+ 7 个模块入口。模块内的页面用页内二级导航（顶部 Tab 或左侧二级菜单）呈现，把「选择页面」的认知负荷从侧栏移到页面内。

### 2.2 命名撞车：同一个名字在多个模块重复

`宿舍管理`（就业/教务/大学部/初高）×4、`退费管理`（咨询/财务/大学部/初高）×4、`缴费管理` ×3、`出勤/成绩/考试/催费/班级管理` 各 ×3。合并域的「学段页签」是对的解法，但只覆盖了教学域；咨询与财务侧的「退费管理」仍是两个完全不同的页面共用一个名字。

**建议**：① 菜单命名带上下文前缀（「大学部·宿舍」「财务·退费」）；② 顶栏常驻「当前位置」面包屑，让用户任何时刻都知道自己在哪个模块的哪一页。

### 2.3 没有真正的「首页」

现状：登录后落到「该账号有权限的第一个页面」——班主任第一眼看到的是花名册，财务第一眼看到的是缴费列表。系统回答的是「你能看什么」，不是「你今天要干什么」。

**建议**：按角色聚合的工作台作为唯一落地页：待我审批 / 临期缴费 / 待接收学员 / 今日出勤异常，一屏说清「今天干什么」，每张待办卡直接跳转到处理页。已有的三处仪表盘（财务概览、初高工作台、就业统计）降级为模块内的分析页。

### 2.4 全局位置感弱

白底顶栏改版后，模块指示更弱了；面包屑只有部分页面有；合并域的学段页签藏在页面内部，切学段要先进页面。

**建议**：学段/模块切换器升格到顶栏（与 LOGO、搜索同一行），任何时候可见、可切。

## 三、视觉体系

### 3.1 三套设计系统并存——颜色统一了，形制没有

| 体系 | 来源 | 特征 |
|---|---|---|
| A | `class/styles/index.css` | 9px 圆角、阴影 rgba(22,33,60,.05)、`.kpi` 左对齐数字 |
| B | `shared-ui/shared-ui.css` | 12px 卡片、7px 按钮、`.stat` 居中大数字 |
| C | Element Plus 默认 | 部分页面直接裸用 |

昨天把三套的颜色拉成了同一套暖红，但圆角、阴影、间距、字号仍是三套。用户从财务页点到班级页，界面「气质」会变。

**建议**：定一套 Token（圆角 8/12px、两级暖阴影、4/8/12/16/24 间距刻度、五级字号），全部组件收敛到一套实现，样式表从三份合成一份。

### 3.2 同样的 KPI 卡，三种长相

- 财务概览：`.stat-card` 居中大数字 + 底部小字
- 初高工作台：`.kpi-card` 另一种排布
- 权限模块：`KpiCard.vue` 又一套

**建议**：统一为一种——左侧 44px 圆角图标底 + 右侧「标签 / 大数字 / 辅助行」，数字一律 `font-variant-numeric: tabular-nums` 对齐。

### 3.3 字号偏小，中文可读性差

现状：正文 13px、表格 12.5px、表头 11.5px、辅助信息 11px。中文汉字在 11–12px 下笔画开始粘连，而这套系统的核心用户是校长、财务、班主任——年龄层偏大、每天盯屏数小时。

**建议**：整体上提一级——正文 14px / 表格 13.5px / 表头 12.5px / 辅助 12px，**12px 设为全站下限**。

### 3.4 对比度不达标（含昨天引入的暖灰也有份）

- `#9C8D88` 文字 on `#F6F3EF` 底 ≈ **2.9:1**
- `#B3A69F` 弱文字 ≈ **2.1:1**

WCAG AA 要求正文 4.5:1。低于 3:1 的文字在正常光线下等于「看得见但看不清」，用户会不自觉地眯眼、前倾——这就是「刺眼/累」的体感来源之一。

**建议**：次要文字改 `#6B5C58`（≈5.9:1）、弱文字改 `#8A7B76`（≈4.6:1）、禁用态才用浅灰。

### 3.5 色彩纪律：一屏五个强调色

财务概览一屏里同时有：收入红、支出绿、待办橙、危险红、品牌红。全都想强调，等于全不强调。

**建议**：立规矩——**一屏一个强调色**；品牌红只给主按钮和关键数字；「收入红/支出绿」保留中国习惯但降饱和；警示统一橙、危险统一红，不混用。

### 3.6 层级靠 1px 边框，界面发「平」

页面底、卡片、弹窗三层几乎同灰度，只靠发丝描边区分，投影太轻。结果是没有「浮起感」，信息分组不明确。

**建议**：三级明度差（底 #F6F3EF / 卡 #FFFFFF / 浮 #FFFFFF+投影）+ 一级柔投影，该重的地方（弹窗、下拉）重下去。

## 四、交互与反馈

### 4.1 表格操作列：一排文字按钮，330px

以学生管理为例：详情/分配/领取/面试/入班/流失 6 个文字按钮横排。目标间距不足 8px，误点率高；触屏场景完全不够用（远低于 44px 最小触控）。

**建议**：行内只放 1 个主动作 + 「更多 ▾」下拉收敛其余；整行可点击进详情；危险动作（流失）放dropdown 底部并二次确认。

### 4.2 筛选区各自为政

有的页面 4 个下拉平铺一行，有的 6 个；状态筛选有的是 Tag 行、有的是下拉。56 页 56 个样。

**建议**：统一 `FilterBar` 组件——常用条件一行排开 + 「高级筛选 ▾」折叠剩余 + 右侧「查询/重置」，全站一套。

### 4.3 加载、空态、错误三缺

- 加载：只有表格中央转圈，首屏白屏时间长时用户以为卡死
- 空态：`el-empty` / 一行灰字「暂无数据」/ 完全空白，三种并存
- 错误：昨天截图里那种红色错误条直接糊脸，无重试入口

**建议**：① 首屏用骨架屏（表格 5 行灰色占位）；② 空状态三件套统一——插图 + 一句文案 + 一个主动作按钮（如「新建第一个学生」）；③ 错误条带「重试」按钮。

### 4.4 破坏性操作无撤销

「标记流失」「退费」只有 confirm 弹窗，点了就生效、不可逆。误触一个学生的流失记录，得找管理员改库。

**建议**：破坏性操作执行后弹 5s「已流失 ✓ 撤销」toast，窗口期内可反悔。这是性价比最高的一个改动。

### 4.5 详情抽屉 720px 塞四个 Tab

档案/跟进历史/缴费单/退费单全塞进右侧抽屉，信息密度过高，横向也放不开表格。

**建议**：详情改「整页 + 顶部 Tab」，或抽屉只放摘要 + 「查看完整档案」跳转。

### 4.6 弹窗表单：两列 660px，长标签换行

「是否一次性付清学费」这类长单选标签在两列布局里被折成两行，对齐难看。

**建议**：表单弹窗单列优先（≤7 个字段才用双列），标签统一上方对齐、宽度不固定。

### 4.7 顶栏搜索是装饰

新顶栏的搜索框只有 placeholder，没有绑定任何行为——用户输入没反应，比没有搜索更糟。

**建议**：接全局搜索（学员/班级/页面，至少支持键盘 ↑↓ 选择回车跳转）；一期做不了就先撤掉，别放假的。

### 4.8 登录页 17 个演示账号平铺

对真实用户是噪音，还暗示「这套系统谁都能进」。

**建议**：折叠成一个「演示账号 ▾」入口，点开才显示；正式环境配置一键隐藏。

## 五、可访问性与响应式

- **焦点管理**：无统一 `focus-visible` 样式，键盘用户完全看不见焦点在哪
- **键盘操作**：表格行无键盘可达路径，快捷键为零
- **小屏**：1366 笔记本上 `fixed="right"` 列 + 横向滚动蹩脚；无任何断点策略，侧栏不可收起
- **建议**：focus 态纳入组件规范；侧栏加「收起成图标条」；表格在小屏降级为卡片列表（字段竖排）

## 六、改版方案（落地路径）

分三步，每步可独立上线、独立验证，不搞「憋大招」：

### 第一步：设计系统 + 三个样板（1 周）
产出 `docs/设计规范.md`（Token + 组件规格）+ 三个可运行样板页：
1. **角色工作台**（待办聚合，验证导航与信息架构）
2. **标杆列表页**（学生管理重写，验证 FilterBar/表格/操作列/骨架屏/空态/撤销）
3. **表单弹窗**（新建学生重写，验证单列表单与校验反馈）

### 第二步：导航重构（跟进）
侧栏模块化、顶栏全局位置指示 + 学段切换器、登录后统一落角色工作台。

### 第三步：全站推广（分批）
56 页按样板替换，先 consult/finance/perm（新模块），后 job/edu/class/class-jh（legacy）。每批跑通再下一批。

### 优先级清单

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 对比度修正（#6B5C58/#8A7B76） | 每天影响每个人，改动量最小 |
| P0 | 字号上提一级（12px 下限） | 同上 |
| P0 | 操作列「更多」收敛 + 撤销 toast | 防误操作，性价比最高 |
| P1 | 角色工作台 + 侧栏模块化 | 解决「找不到、不知道干什么」 |
| P1 | 三套样式表合一 + KPI 卡统一 | 解决「像三个产品」 |
| P1 | 骨架屏 / 空态三件套 / 错误重试 | 解决「费劲、心慌」 |
| P2 | 顶栏真实全局搜索 | 依赖第一步的组件规范 |
| P2 | 响应式（侧栏收起 / 表格卡片化） | 使用场景决定要不要做 |

## 附：本轮顺手修掉的后端 bug

审查期间发现并修复：`server-job/src/teaching/class/` 下三个仓储的 `countStudents()` 漏写 `groupBy('class_id')`，在 MySQL 8 默认 `only_full_group_by` 模式下报 1140 错误（表现为班级人数统计接口 500）。三处已补 `groupBy` 并加注释，`tsc --noEmit` 通过。**需重启后端生效。**
